GATES Implementation Plan

Two workstreams: A) GIS vector pipeline (GeoPandas, OGR/Shapely, GeoParquet, PostGIS, GeoServer) and B) PII protection (Presidio, OpenBao) and encryption at rest (MinIO now, Ceph in production).

Assumptions

  • Source CRS must be declared in config when .prj is missing. It is never guessed.
  • Layers keep the latest version only (no history).
  • GeoServer is internal-only. Shapefile and GeoPackage input are both accepted.
  • PII is pseudonymized or masked, not reversible.
  • PoC: single-node OpenBao with Shamir unseal, MinIO. Production: HA OpenBao and Ceph.
  • You run the commands. Nothing is executed on your behalf.

A · GIS vector pipeline 8 steps

Shapefile / GPKG→Ingest→Validate→ Standardize→GeoParquet (MinIO)→PostGIS→ GeoServer→DataHub

A separate DAG factory, driven by geo_registry.yaml, outside the dbt/Trino medallion.

A1 Infrastructure
  • Add postgis/postgis (separate from the existing Postgres), GeoServer with a data-dir volume, and a geo MinIO bucket in docker-compose.demo.yml.
  • Add geopandas, pyogrio, shapely, pyarrow, geoalchemy2, requests to the Airflow requirements.
  • Add PostGIS and GeoServer host and credentials to .env.example.
Done whenServices are healthy, import geopandas, pyogrio works in Airflow, and SELECT postgis_version() answers.
A2 Config and registry

  • orchestration/geo_registry.yaml: one entry per layer (folder, pattern, agency, schedule).

Done whenThe loader returns the layer config and rejects one missing source_crs or unique_key.
A3 Ingest
  • ingestion/ingest_shapefile.py: read .shp / .zip / .gpkg, check sidecars, handle DBF encoding, apply alias map for truncated column names.
  • Copy originals untouched to geo/<layer>/raw/<run_id>/.
  • Write a manifest: feature count, CRS found, geometry types, columns.
Done whenThe sample facilities file ingests with a correct manifest, and a missing .prj without a configured CRS gives a clear error.

B · PII protection and encryption at rest 5 steps

Ingest→GX validation (real values)→ pii_protection (Presidio + OpenBao)→Load→Storage with SSE

Field-level protection is a pipeline step. Encryption at rest is infrastructure. You need both.

B1 OpenBao in compose
  • OpenBao with Raft storage on a dedicated volume; initialize and unseal.
  • Enable transit and kv. Create keys pii-hmac (and pii-enc only if reversibility is required).
  • AppRole with a policy allowing HMAC and encrypt only, with no decrypt. Enable a file audit device.
  • Dev mode for local only, with a guard against use in the AWS environment.
Done whenThe loader AppRole can call HMAC and is denied decrypt and other keys.
B2 PII tags in the schema
  • Add pii: (class, treatment) to fields in schema_project_monitoring.yaml: principal_investigator → pseudonymize, submitted_by → mask.
  • Extend the config DB for rd_equipment_inventory; reject unknown treatments.
B3 pii_protection module
  • common/pii_protection.py: Transit batch HMAC for pseudonyms, local masking, Presidio BatchAnalyzerEngine on free_text columns with Philippine ID and phone recognizers and a custom Transit operator.
  • Fail closed: if OpenBao is unreachable, the task fails and writes no plaintext.
  • Hook into _make_promote_to_staging after validation, before load_validated_batch, and onto the quarantine path. Land it behind a config flag, off by default.
  • Discovery check on untagged columns; scrub logs, GX docs and DataHub samples; reuse for geo attribute tables.
Done whenStaging has no plaintext PI names or emails, pseudonyms are stable across runs, and with OpenBao stopped the task fails without writing.
B4 Encryption at rest (PoC)
  • MinIO KES backed by OpenBao; default SSE-KMS on the lake and geo buckets.
  • Keep encrypted EBS volumes; put PostGIS and OpenBao data on them.
  • Test KES with your OpenBao version first. If it fails, fall back to MinIO SSE-S3 and record the gap.
Done whenAn object read directly from the volume is unreadable, and revoking the key makes objects unreadable.
B5 Production note
  • docs/PRODUCTION_SECURITY.md: Ceph RGW SSE with OpenBao, OSD encryption, HA Raft and unseal strategy, token renewal via agent, TLS/mTLS.
  • The RGW and OpenBao compatibility test is a first-phase production item.

Verification

  • Geo: good sample passes; bad sample quarantined with specific reasons; re-run idempotent; WMS and WFS return features.
  • Security: no plaintext PII in staging, bronze, silver, gold or quarantine; loader role cannot decrypt; encrypted objects unreadable without OpenBao.
  • Regression: the project_monitoring and rd_equipment_inventory DAGs still pass end to end after each step.

Risks

  • Single-node OpenBao is a single point of failure: fine for the PoC, not for production.
  • Presidio recall on Filipino names is imperfect; treat free-text scanning as risk reduction.
  • A wrong or missing CRS is the most likely silent geo error.
  • KES-with-OpenBao and RGW-with-OpenBao compatibility are unverified assumptions.
  • Pseudonymized data is still personal data under the Philippine Data Privacy Act.
